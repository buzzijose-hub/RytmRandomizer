## 1. Safety model amendment (Decision Gate ① — APPROVED 2026-07-18)

Maintainer decision, verbatim intent: *"live connection, but everything passive by default — best of both worlds: we know right away if we have connection issues, and we don't interrupt any sound output."* The current hard rule ("only `python -m rytm_randomizer.app --arm` opens a real MIDI port") is superseded by the **Live-but-Passive model**:

- **On launch (no gate):** port *enumeration* (opens nothing) + automatic *input-only* opens for detected Elektron-pattern ports, so connection health is known immediately. Phases: `disconnected → searching → listening`. **Input opens are strictly read-only; no output port is opened and no byte is transmitted — the live connection cannot interrupt the operator's sound output.**
- **Transmission (always gated):** every outbound byte routes through a single `senders/` **ArmedApply** seam — in-UI Arm toggle + per-action confirmation (optional physical-gesture confirm for destructive sends). Phases: `listening → armed`. Never auto-re-arm after reconnect.
- **Mutation safety (anti-Total-Recall):** any kit/sound write is preceded by an automatic timestamped backup capture, and every sync surface states its direction explicitly.
- **Enforcement:** `tests/architecture/test_armed_entry_points.py` whitelists ArmedApply as the only `mido_provider`/`real_midi_adapter` **output** consumer, repo-wide (not package-scoped); a companion assertion confirms the launch/listen path opens inputs only. CLAUDE.md rule 8, `.claude/rules/architecture.md`, and README safety text are amended in this bundle to state the Live-but-Passive model.
